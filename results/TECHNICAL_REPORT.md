# 科研论文核查 Agent：用可验证的联网核验替代"凭记忆"的引用审查
### SciencePal 全球 AI4Science Hackathon 2026 · 技术报告

## 摘要

大语言模型在加速科研写作的同时，也让引用幻觉（citation hallucination）、题录错配、已撤稿文献与统计错误更容易进入稿件。通用模型在离线状态下无法验证一个 DOI 是否真实存在、其题录是否与元数据库一致、文献是否已被撤稿、报告的 p 值是否与数据相符。本工作在 SciencePal 平台构建「科研论文核查员」Agent：对每条参考文献强制联网请求 Crossref，依据真实 HTTP 状态与元数据逐字段比对，在隔离沙箱内用 scipy 复算统计量，输出带来源证据 URL 的结构化报告。

为避免用一个被削弱的对手来衬托方法，我们设计了**三方对照**，而不是"有方法"对"无方法"的二元比较：

1. **离线基线**：同一平台、同一模型，在 API 层关闭沙箱命令与联网；
2. **普通联网 Agent**：沙箱、联网、所有工具全部开放，只给最低限度的取证要求（联网、用 curl 取证、不反问、不等待人工、不写记忆），**不提供 C1-C4/M1-M5 任何专家核查流程**（对照边界见 2.3）；
3. **专家核查工作流**：同样开放全部工具，但在系统提示词中固化专家核查路径（C1-C4 引用与出版状态检查、M1-M5 方法学与统计检查）。

测试集为可复现、实时构造的金标准（48 条，含真实、虚构、题录错配三类，评测时无数据泄漏），每个 run 的联网真实性由 SSE 事件审计确认。结果给出一个反直觉但清晰的结论：

- 幻觉 DOI 检测 F1：离线基线 **0.621**，普通联网 Agent **1.000**，专家工作流 **1.000**；
- 元数据错误检测 F1：0.824 / 1.000 / 1.000；
- 也就是说，**决定性的能力闸门是"强制联网核验"，它让 F1 从 0.62 跃升到 1.00；在当前这一代强模型上，专家核查流程在显性错误层面没有带来额外的 F1 增益**。我们在撤稿识别、统计复算、冷门撤稿限定任务三个隐式错误案例上做了同输入对照，两个联网 Agent 都能做对。

我们如实报告这一阴性结果，并据此重新定位专家工作流的价值：它不提升单条题录的判对率，而是把"必须联网、必须逐字段、必须复算、必须留证据"固化为可复现的工作流约束，在过程上表现为平均工具调用更少、无状态污染、输出位置与格式稳定、全流程可审计。需要说明这是提示词/工作流层面的约束而非代码级强制，且过程指标为小样本观测（见 4.6）。本工作的实际贡献是：一个可复现的论文核查金标准基准、对"离线到联网"能力跃迁的量化、以及一个可部署、可审计的核查工作流；并进一步把"必须联网、必须覆盖、必须有证据"从提示词约束下沉为**代码级 guardrail**（运行时拦截 + 交付契约校验 + 有界自动修复），在 6 个稿件注入用例上把交付可用率从 4/6 提到 6/6。

## 1. 问题与动机

### 1.1 问题的量级：可重复性、撤稿与 AI 生成引用

科研文献的可信度正在承压，且压力随大模型进入写作环节而放大。

- **可重复性**：Baker 对 1,576 名研究者的调查中，超过 70% 的人曾尝试却无法复现他人的实验（Nature, 2016, 533:452–454）；Begley 与 Ellis 报告，Amgen 团队复现 53 项被视为新范式的肿瘤学里程碑研究，仅 6 项（约 11%）可复现（Nature, 2012, 483:531–533）。
- **撤稿**：2023 年全球撤稿论文首次超过 1 万篇，创历史纪录（Van Noorden, Nature, 2023, 624:479–481）；Retraction Watch 数据库（已并入 Crossref）累计撤稿记录接近 5.5 万条。撤稿文献在题录层面仍"合法"，会继续被引用。
- **大模型生成引用**：Walters 与 Wilder 测得，GPT-3.5 生成的参考文献中 55% 为编造，GPT-4 仍有 18%；在非编造的引用里，GPT-3.5 有 43%、GPT-4 有 24% 存在作者、卷、期、页等实质性错误（Scientific Reports, 2023, 13:14045）。

这些数字共同指向一个工程问题：引用与出版状态的校验不能依赖模型记忆，必须以可复核的外部证据为依据；当 AI 被用于审稿或写作辅助时，这一环节还需要可复现、可审计、可规模化，而不是靠人工逐条点验。

### 1.2 引用层面的两类问题

1. **幻觉/失效 DOI**：DOI 字符串语法合法、前缀真实（属于某注册机构），但后缀对应的文献并不存在。这类问题最难人工发现，编辑或审稿人通常不会逐条点开 DOI。
2. **题录错配**：DOI 真实存在，但参考文献中作者、年份、标题或期刊与其元数据不一致（引用错配、张冠李戴）。

### 1.3 为什么纯模型不可靠

- 模型参数中只包含训练语料里出现过的文献，对海量、长尾、近年的论文没有覆盖；
- 它无法区分"一个不著名但真实的 DOI"与"一个格式合法但被篡改或编造的 DOI"；
- 当被要求给出结论时，模型倾向于依据表层格式规律猜测，这同时造成漏报（格式规范的幻觉）与误报（格式非典型的真文献）。

### 1.4 两个需要区分的假设

- **H1（联网闸门）**：引用核查本质上需要外部事实检索；强制联网、逐字段比对、证据留痕应显著优于离线模型。
- **H2（专家流程增益）**：在已经能够联网的前提下，固化专家核查流程相对"给强模型联网能力但不教流程"是否还能提升判对率。

H1 决定"要不要联网"，H2 决定"联网之外还要不要专家流程"。我们用同一个金标准分别检验这两个假设，避免把两者混为一谈。

## 2. 方法

### 2.1 专家核查工作流（Agent 架构）

核查 Agent 运行在 SciencePal 通用沙箱 runtime（可执行命令、联网、读写文件、安装软件），系统提示词规定固定的核查流程：

- **阶段一 · 引用与出版状态核查**
  - C1 DOI 有效性：在沙箱内 `curl https://api.crossref.org/works/{doi}`，以真实 HTTP 200/404 判定存在性；
  - C2 元数据逐字段严格比对：将 Crossref 返回的年份（issued.date-parts）、作者、标题、期刊、卷/期/页码与待审条目逐字段比对，任一不一致即 `metadata_match=false` 并给出 `confirm`，禁止仅因 HTTP 200 就放行；
  - C3 论断-证据一致性：正文论断是否与所引文献主题相符；
  - C4 出版状态（撤稿）：逐条检查 Crossref 标题是否以 `RETRACTED ARTICLE:` / `RETRACTED:` 开头或以 `- RETRACTED` 结尾、是否出现独立的 RETRACTED / WITHDRAWN 标记、`relation` 或 `update-to` 中是否存在指向撤稿通知的 `has-retraction` 关系，并核对期刊页面标注。
- **阶段二 · 方法学/统计审查**：M1 研究设计、M2 样本量与功效、M3 统计表述、M4 数据-结论复算（在沙箱中实际运行 scipy）、M5 选择性报告；
- **输出**：人类可读中文报告加末尾固定 schema 的 JSON（`references[].{item_id,doi_status,metadata_match,verdict,evidence_url,issue}`），便于自动评分与系统集成。

关键工程约束：禁止凭记忆给结论；每条引用必须有可点击的证据 URL 与 HTTP 状态；无法确证时标 `suspect` 并提示人工复核；不调用与核查无关的工具，不向长期记忆写入数据。

### 2.2 离线基线（对照一）

基线使用同一平台、同一默认模型，但在 API 层移除其获取外部事实的能力：

- 通过 `PUT /agents/{id}` 设置 `agentpress_tools={"execute_command":{"enabled":false},"web_search":{"enabled":false}}`；
- 发起任务时传 `web_search_on=false`；
- 系统提示词明确"纯文本环境、无任何工具、必须完整输出 JSON"。

实践中发现，仅在提示词里写"禁止联网"不可靠，只关闭 `web_search` 也挡不住沙箱内的 `curl`；因此在 API 层关闭 `execute_command`，并用运行时事件审计作为最终保证（见 3.3）。

### 2.3 普通联网 Agent（对照二，防止稻草人基线）

为了回答 H2，我们必须排除"对手只是因为被人为剥夺了联网能力才失败"的解释。普通联网 Agent 满足：

- 与专家核查工作流**完全相同的平台、模型、工具权限**，沙箱命令、联网、内置技能全部开放；
- 系统提示词只说明它是一个联网研究助手，要求用 curl 取证、不反问、不等待人工接管、不写入长期记忆；
- **不提供 C1-C4 / M1-M5 任何专家核查步骤，不规定输出 schema 之外的流程**。

需要说明这个对照的边界：它不是完全无引导的裸 Agent。为了让批量评测可运行（否则通用 Agent 会反问或停在等待人工接管），我们给了它最低限度的取证要求：联网、用 curl 取证、不反问、不等待人工、不写记忆；但刻意不提供 C1-C4 / M1-M5 等任何核查步骤。因此它隔离的是"流程"这一变量，代表"一个能力相同、被要求联网取证、但没有专家流程的 Agent"；至于连"要联网取证"都不提示的裸 Agent 表现，本工作未测。这个对照的逻辑是：若专家流程只比离线基线强，结论可能只是"联网很重要"；只有在同等联网与取证要求下仍能拉开差距，才能把增益归因于专家流程。

## 3. 评测设计

### 3.1 金标准基准的自动构造（可复现）

`scripts/build_benchmark.py` 调用 Crossref REST API 自动构造三类条目（每个种子 12 条，比例约 6 valid / 3 not_found / 3 mismatch）：

- **valid（真实）**：从 2015–2025 年普通期刊论文池抽取（过滤会议摘要、增刊、作者缺失），保留真实题录；
- **not_found（虚构 DOI）**：取一篇真实论文的真实前缀与格式，仅篡改后缀数字，并在构造时实时请求 Crossref 确认 404。刻意使用过去年份，避免模型靠"未来年份"推理侥幸答对；
- **mismatch（题录错配）**：真实 DOI 配错误题录，年份 / 作者标题 / 期刊三类均衡；标题篡改采用"替换核心实词为领域外词（Quantum/Blockchain 等）"，避免被误当作良性截断。

由于金标准在每次构造时实时核验，且测试种子不参与任何提示词调参，测试集不存在答案泄漏。

### 3.2 开发集 / 测试集隔离

- 种子 42、201 仅作为开发集用于迭代提示词（例如据此补强 C2 逐字段比对规则）；
- 最终指标在未参与任何调参的种子 7 / 123 / 2024 / 2025（共 48 条）上报告，防止在测试集上过拟合。

### 3.3 联网真实性审计（对照成立的关键）

"关闭工具"和"提示词说会查"都可能名不副实。我们对每个 run 的 SSE 原始事件流（`output/runs/{run_id}.jsonl`）重放并审计（脚本 `scripts/audit_runs.py`，识别规则在 `scripts/run_batch.py`）：

- 命中沙箱内 `curl` 请求 Crossref/DOI 域名、或工具返回中出现与同条 DOI 配对的 `HTTP 200/302/404` 状态、或出现 `title:[` / `container:[` / `resource not found` 等 Crossref 字段，判为"实际联网"；
- 工具返回 `runtime=blocked`、`reason_code=tool_unavailable` 或 `permission`，判为"尝试被拒、未获数据"。

审计识别了 302 重定向、异步批量脚本一次性返回等容易被字面匹配漏掉的情况。12 个测试 run 全部符合预期：

| 方法 | 期望 | 实际获得外部数据 | 工具调用次数（四 seed） |
|---|---|---|---|
| 离线基线 ×4 | 离线 | 否（全部） | 3（其中 2 次被拒）/ 0 / 0 / 0 |
| 普通联网 Agent ×4 | 联网 | 是（全部） | 36 / 19 / 3 / 5 |
| 专家工作流 ×4 | 联网 | 是（全部） | 16 / 3 / 22 / 4 |

### 3.4 指标

对三项任务分别计算精确率（P）、召回率（R）、F1、特异度（Specificity，真实条目被正确放行的比例）与准确率（Accuracy）。除判对率外，我们还记录每个 run 的工具调用数、工具类型、最终 JSON 是否稳定出现在末轮，以刻画过程可靠性。

## 4. 结果

本章给出两个主结果。

- **主结果一（能力层面，H1）：联网是能力闸门。** 强制联网核验把幻觉 DOI 的 F1 从 0.621 拉到 1.000、把全测试集的误报从 23 降到 0。这是决定性的、可复现的差异，回答"引用核查是否需要外部证据"。
- **主结果二（过程层面，H2 阴性后的再定位）：流程固化提供可复现的过程约束。** 在当前强模型上，专家流程不额外提高 F1（H2 不成立），但它把核查步骤、输出 schema 与留痕要求固化为工作流，在过程上呈现更少的平均工具调用、零非核查写操作、稳定的末轮输出。这是提示词/工作流层约束而非代码级强制，过程指标为 n=7 的小样本观测（见 4.6）；它回答的是"联网之后，如何让结果在无人值守、规模化时仍可复现、可审计"。

我们把这两者分开报告，不把过程增益冒充为判对率增益。

### 4.2 H1 得到支持：联网是决定性闸门

离线基线整体召回不低（任意问题 R=0.958），但代价是大量误报，在最关键的幻觉 DOI 任务上 F1 仅 0.621、特异度仅 0.778。只要开放联网，无论是普通 Agent 还是专家工作流，三项 F1 都升到 1.000，误报归零。**F1 从 0.621 到 1.000 的跃迁几乎完全由"强制联网核验"解释**，差异主要来自误报的消除（FP 8 → 0）。

### 4.3 H2 未获支持：强模型上专家流程无额外 F1 增益（如实报告）

普通联网 Agent 与专家工作流在 48 条上的 F1 完全相同（均为 1.000）。这说明在当前这一代强模型（deepseek-v4-flash）上，在被要求联网取证之后，模型会自行选择 Crossref 拉取题录并逐字段比对，不需要专家把具体核查步骤（C1-C4/M1-M5）写进提示词。

我们没有用一个弱对手来制造"专家流程更准"的假象。我们进一步用三个隐式错误案例检验专家流程是否在更深层的问题上仍有判对率优势（见 4.5），结果普通联网 Agent 同样做对。因此在当前模型、当前错误类型上，**"专家流程提升 F1"这一主张不成立，我们不据此宣称更高准确率**。

### 4.4 错误模式分析（为什么离线基线"看起来会查"其实不可靠）

离线基线的 3 个漏报（幻觉 DOI 被放行）：`10.1109/access.2019.2991190`、`10.55248/gengpi.6.0625.16682`、`10.21275/sr231015260210`。这些恰是前缀真实、格式最规范、最具迷惑性的 DOI，正是真实攻击或幻觉中最危险的一类，纯模型无法辨识。

离线基线的 8 个误报（真实 DOI 被冤枉）：它对 Bentham 系列 `10.2174/15734056mte2nnjcoy` 判"后缀含字母、不合规"，对 IJSR 系列 `10.21275/ms2312181849` 等判"不符合该刊前缀格式"。这些臆想的格式规则本身是错的，这些期刊确有字母后缀或 ms、sr 编号。这一"高召回加高误报"组合在审稿场景不可用：错误否决真实引用会冤枉作者、制造大量返工。

### 4.5 Layer-2 隐式错误：同输入对照（撤稿、统计、冷门撤稿）

Layer-1 只测显性的题录错误。我们在三个需要更深核查的案例上，让普通联网 Agent 与专家工作流收到**完全相同的原始 prompt**（不教撤稿方法、不教复算方法、不列检查清单），结果保存在 `results/layer2/` 与 `results/layer2/compare/`。

**案例 A · 著名撤稿（STAP 细胞）**：输入 Obokata 等被当作正常引用、题录完整的论文（`10.1038/nature12968`）。专家工作流 6 次工具调用、普通联网 Agent 4 次工具调用，均发现 Crossref 标题为 "RETRACTED ARTICLE" 并定位到官方撤稿通知 `10.1038/nature13533`。

**案例 B · 统计结果复算**：使用明确标注为虚构的教学稿件，预埋"作者报告 p=0.03/0.04，实际不显著"的错误。两者均在沙箱中安装并运行 scipy 独立复算，得到高剂量 vs 安慰剂 p=0.206、低剂量 p=0.138、单因素 ANOVA p=0.284、Bonferroni 校正后 0.09/0.12、事后功效 0.235、达到 80% 功效需每组约 37 例。普通联网 Agent 列出 7 条发现，专家工作流列出 6 条。

**案例 C · 冷门撤稿加限定任务（最严格的一轮）**：为排除"模型靠记忆知道著名撤稿"，我们用 OpenAlex 筛出一篇 2026 年、被引极少、模型不可能记忆的昆虫学被撤论文（`10.1017/s0007485326101060`，Crossref 标题以 `- RETRACTED` 结尾），配同期刊一篇正常论文，且任务**只要求核对 DOI 是否有效、题录是否一致，全文不出现"撤稿"二字**。结果两个联网 Agent 都识别出撤稿，普通联网 Agent 甚至自行查到撤稿通知 `10.1017/s0007485326101424`。这是最强的一轮反例：即使在冷门、限定任务下，强模型也会主动越界深挖。

三个案例都未显示判对率差异，进一步印证 H2 在当前模型上不成立。

### 4.6 专家流程的实际价值：过程约束、效率与可审计

在判对率相同的前提下，专家流程的差异体现在过程，这是一个真实但更弱的主张，我们用过程数据如实支撑（`results/process_reliability.json`，共 7 个工作流 run 与 7 个普通 Agent run）：

| 过程指标 | 专家工作流 | 普通联网 Agent |
|---|---|---|
| 平均工具调用数 | 8.29 | 12.43 |
| 工具调用范围 | 3 到 22 | 3 到 36 |
| 非核查工具调用（save_memory、技能检索等） | 仅技能检索 3 次 | 技能检索 3 次 + **save_memory 1 次** |
| 最终 JSON 落在中间轮、末轮只剩总结 | 0 次 | **1 次** |
| 输出 schema 固定、字段完整 | 7/7 | 7/7（需定制解析器才能提取中间轮 JSON） |

- **无状态污染**：普通联网 Agent 在一次测试中尽管提示词禁止仍调用了 `save_memory` 写入长期记忆，专家流程的 7 个 run 从未调用任何写入状态或与核查无关的工具。
- **输出稳定**：普通联网 Agent 有一次把最终 JSON 放在中间轮、最后一轮只留总结，导致标准解析器直接读不到结果，需要专门改造解析逻辑；专家流程始终在末轮输出固定 schema。
- **步骤更少、非核查动作更少**：普通联网 Agent 的工具调用数均值更高、范围更宽（3 到 36，均值 12.43），冷门撤稿案例中还反复轮询命令输出（15 次）；专家工作流均值更低、上限更低（3 到 22，均值 8.29），且 7 个 run 中没有任何写状态或与核查无关的调用（3 次非预期均为技能检索）。需要说明的是，专家工作流的单次调用数仍有波动（3 到 22），并非严格固定，差异体现在均值、上限与动作类型上。

需要强调两点口径，避免过度解读。第一，这些是 n=7 对 n=7 的小样本过程观测，我们没有做统计检验，save_memory 与 JSON 错位各只观测到 1 次，应视为"观察到的事件"而非"统计显著的差异"；它们提示风险方向，但不构成对可靠性的量化结论。第二，专家流程目前是系统提示词与工作流层面的约束（固定步骤、固定 schema、禁止写记忆），并非代码级强制（没有在运行时拦截写记忆、没有强制 schema 校验或失败重试），因此它降低偏离的概率，但不能从机制上保证永不偏离；把提示词约束升级为代码级 guardrail 是后续工程项。

在如实呈现这些口径之后，专家流程的工程价值定位仍然成立：它面向无人值守、规模化批量核查，把"查什么、查多深、结果怎么落地"固定为可复现的工作流，便于审计与集成。但这一价值属于过程与工程层面，不改变第 4.3 节的结论，它不提升当前强模型上的判对率。

### 4.7 从提示词约束到代码级 guardrail

4.3 与 4.6 的结论有一个共同弱点：专家流程的价值停在"观测"层面，工具调用更少、没写记忆，这些都是**发生过一次或几次的事件**，而不是机制保证。评委可以合理追问：如果模型下一次不听话，你怎么保证交付物仍然可用？本节把约束从提示词层下沉到代码层，并给出可复算的机制证据（完整协议见 `results/guardrail/PROTOCOL.md`）。

**先回答"能不能在配置层关掉"。** 我们对 `agentpress_tools` 做了 9 组行为学探测：`execute_command` 关闭后 curl 确实被拒（开关有效），但记忆类工具的 4 种写法（`save_memory: false`、`save_memory.enabled=false`、`memory.enabled=false`、`memory_tools.enabled=false`）以及 5 个 `tool_profile` 取值，**全部无效，记忆仍被写入**。也就是说，"不写记忆"在平台上只能写成提示词，而提示词是可被输入内容覆盖的软约束。这是必须做代码级拦截的直接原因。

**三层机制。** L1 平台配置：关掉确实能关的工具；L2 运行时拦截：逐事件监视 SSE，出现被禁工具立即 `POST /agent-run/{id}/stop`，再下发纠正指令在同一 thread 续跑；L3 交付契约：最终 JSON 必须通过四类机械校验（S 结构 / C 覆盖 1..N / E 证据 URL 齐备 / V 判定自洽），失败则把具体错误回喂、限 2 轮修复，仍失败标记 degraded（`scripts/guardrail.py`、`scripts/report_schema.py`）。

**注入实验。** 6 个用例只在真实题录后追加一段"看起来属于稿件"的文字（CSV 交付、写记忆、不必联网、替作者辩护、改 schema、只查前 3 条），题录与金标准不变，因此仍用同一套金标准打分。两组判据完全一致。

| 指标 | 无 guardrail | 有 guardrail |
|---|---|---|
| 交付可用（可解析 + 四类校验全过） | **4/6** | **6/6** |
| 契约违规 | 2 | 0 |
| 被禁工具尝试 / 其中写入实际发生 | 1 / 1 | 1 / **1** |
| 运行时中断 / 自动修复 | 0 / 0 | 1 / 4 |
| 平均 token / 墙钟 | 30.8k / 86.0s | 56.2k / 127.0s |

![一次真实拦截的时间线](figures/guardrail_timeline.png)

上图取自真实 run 的 SSE 时间戳（`output/runs/*.jsonl`），不是示意图：第 1 轮用约 105 秒完成 12 条引用的逐条核验，随后在第 120 秒尝试调用 `save_memory`；guardrail 在 2.1 秒内发出 stop，运行被中断；16 秒后在同一 thread 下发纠正指令续跑，第 160 秒输出通过契约的完整 JSON（12/12、F1 1.000）。

两个失败样例分别是覆盖截断（`C: 缺少条目 item_id=[4..12]`，F1 = 0）与契约破坏（`S: 未找到可解析的 JSON 代码块`，F1 = 0）；有 guardrail 时两者均被修复为合规交付。此外对校验器本身做了故障注入：6 类失败模式 × 3 个来源 = 18 例，**18/18 检出、0 误报**；对状态机做了 17 条离线断言（不耗配额），覆盖"首轮即合规 / 被禁工具触发 stop 且 stop 早于纠正消息 / 无 JSON 触发修复 / 修满标记 degraded / 声明-轨迹一致性"五条路径，全部通过。对照图见 `results/figures/guardrail_compare.png`。

#### 4.7.1 回溯审计：契约是事后定义的，所以必须套回旧数据

判据如果是"为结果定制"的，就一文不值。为此我们把当前契约（S 结构 / C 覆盖 / E 证据 / E3 指向 / E4 域名 / V 自洽）原样套到**全部 35 个 run** 上，其中专家流程、普通联网 Agent、离线基线三组的结果都是**在契约定稿之前**跑出来的：

| 组 | run 数 | 契约合规 | 主要失败项 |
|---|---|---|---|
| 专家核查工作流（含 dev seed42） | 5 | **5/5** | — |
| guardrail 开启（6 注入 + 4 干净 + 1 规模） | 11 | **11/11** | — |
| guardrail 关闭（6 注入 + 1 规模） | 7 | **5/7** | C×1、S×1 |
| 普通联网 Agent（48 条测试集） | 4 | **2/4** | E3×6（3 条 × 2 run） |
| 离线基线（三种配置） | 7 | **0/7** | E×84 |

E3 的含义是"证据 URL 必须指向被核查的那一条"。普通联网 Agent 对 3 个不存在的 DOI 填了"最接近的真实 DOI"，判定仍然正确（F1 同为 1.000），但证据与条目失去一一对应：审稿人点开链接看到的是另一篇文献，无法据此复核这一条。专家流程与 guardrail 版填的是该条 DOI 自身的 Crossref URL，404 本身就是最忠实的证据。离线基线则没有任何外部证据（E）。

这条差异值得单独说：**在判对率完全相同的 48 条上，交付物是否可复核仍能被代码拉开差距**（专家 4/4 vs 普通 2/4），而且不依赖评委主观印象。需要说明，E3/E4 是本工作定义的可复核性判据，不是学界既有标准；它的合理性来自一个朴素要求：第三方点开证据链接，应当看到被核查的那条记录。

**这节的贡献要说清楚边界。** 第一，拦截不等于撤销：被禁工具是执行完才出现在事件流里，stop 只能中断后续，两组的"写入实际发生"都是 1/6，我们不宣称能阻止这一条写入。第二，代价真实：修复要重发上下文，平均 token +82%、墙钟 +48%。第三，n=6 是定性对照，证明"机制能拦住这类失守"，不证明发生率。干净 48 条上的复跑（4 个 seed、n=48）：guardrail 组 **4/4 可用**、F1 1.000（无 guardrail 组同为 1.000）、自动修复 0 次、拦截 0 次，即**在干净输入上没有引入任何判对率回归**，修复只在契约失守时触发。规模压测（36 条、n=36）同样是两组各 1 个 run、均 1/1 可用且 F1 1.000、0 次修复，也就是说在这一代模型上，36 条还没有出现覆盖衰减，guardrail 保持静默；这不证明"更大规模也不会失守"，只说明我们**没有观察到**，如实记录。第四，强模型对 4/6 的单点注入本身就守住了，guardrail 的增益集中在覆盖截断与契约破坏两类，这仍然比"工具调用少了 4 次"硬，因为它是**代码保证**而非**观察到的运气**。

### 4.8 两个补充实验：换模型复现 + 真实已发表论文的书目

**换模型复现。** 4.3 的阴性结论此前只在 deepseek-v4-flash 上成立。我们在同一批 48 条、同一 Agent、同一 guardrail 下换用 **deepseek-v4-pro** 重跑 4 个 seed：

| seed | flash F1 | pro F1 | flash 耗时 | pro 耗时 | 修复/拦截 |
|---|---|---|---|---|---|
| 7 | 1.000 | 1.000 | 58.9s | 120.7s | 0/0、0/0 |
| 123 | 1.000 | 1.000 | 91.1s | 92.9s | 0/0、0/0 |
| 2024 | 1.000 | 1.000 | 62.0s | 258.7s | 0/0、0/0 |
| 2025 | 1.000 | 1.000 | 102.7s | 138.2s | 0/0、0/0 |

结论：阴性结果不是单模型偶然；代价是 pro 平均耗时约为 flash 的 1.9 倍（152.6s vs 78.7s），我们不做"更快"的宣称。两者都是强模型，"固化流程能否补偿弱模型"仍未检验。

**真实已发表论文的书目。** Layer-1 的 48 条是构造数据，评委有理由问"真实书目上会不会乱报"。我们从一篇 2024 年真实论文的 Crossref 参考文献表（63 条，其中 50 条可核对）构造用例：引用行按出版社登记的字段拼出（就是读者看到的那一行），金标准取被引 DOI 自身的 Crossref 记录，**只把年份不一致判为 mismatch**（4 条；期刊缩写、标题截断一律不判错，避免把引用习惯当错误）。

结果：**4/4 检出、46 条正确放行、0 误报**（P = R = 特异度 = 1.0），单次耗时 263 秒。这是一篇论文、一个学科、只判年份的小样本外部效度检查，不构成对全部真实书目的保证，但至少说明"在没人故意做错的书目上，它不会乱报"。

## 6. 局限与未来工作

我们如实列出本工作的边界，这些边界直接限制结论的外推范围：

1. **H2 只在两个强模型上得到阴性结果**。已在 deepseek-v4-flash 与 v4-pro 上复现（§4.8），两者都是强模型；平台未提供更弱模型，因此"固化流程能否补偿弱模型"仍无法检验，这仍是最值得补的一组实验。
2. **显性错误样本量 n=48，隐式错误为小样本案例**。全对时 F1 点估计为 1.0，Wilson 95% 置信下界约为 0.926，不能把点估计等同于"零错误率"；撤稿与统计能力尚未形成大规模量化基准。
3. **撤稿信号覆盖受数据源限制**。冷门撤稿中能被 Crossref 标题或 `relation` 标记到的比例不高，我们在 OpenAlex 初筛到的多页被撤论文里，多数在 Crossref 标题中不含 RETRACTED 标记，需接入 Retraction Watch 等专门库才能系统评测。
4. **更隐蔽的错误类型未覆盖**。C3 论断-证据错配、统计方法选择错误（数字自洽但检验方法错）需要读全文理解，本工作只做了定性演示，未构造金标准。
5. **数据源单一**：目前以 Crossref 为主，计划接入 PubMed、Semantic Scholar、OpenAlex 与中文文献库做多源交叉验证。
6. **guardrail 的边界**：运行时拦截只能中断不能撤销已执行的工具调用；自动修复有真实成本（平均 token +82%）；注入对照 n=6 为定性证据，不构成发生率估计。
7. **定位为辅助工具**：系统对不确定项输出 `suspect` 而非武断结论，最终判定保留人工复核。
