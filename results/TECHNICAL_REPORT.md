# 科研论文核查 Agent：用可验证的联网核验替代“凭记忆”的引用审查
### SciencePal 全球 AI4Science Hackathon 2026 · 技术报告

## 摘要

大语言模型在加速科研写作的同时，也让**引用幻觉（citation hallucination）**与题录错配更容易进入稿件。通用模型在离线状态下无法验证一个 DOI 是否真实存在、其题录是否与元数据库一致。本工作在 SciencePal 平台构建「科研论文核查员」Agent：它对每条参考文献**强制联网**请求 Crossref，依据真实 HTTP 状态与元数据进行两阶段（引用核查 + 方法学审查）判定，并输出带来源证据的结构化报告。为严谨验证其价值，本工作构建了一个**带金标准、可复现的引用核查基准**（48 条测试集，含真实、虚构、题录错配三类），并设计了**经 SSE 事件审计确认零外部数据访问**的纯模型离线基线。结果显示：核查 Agent 在幻觉 DOI 检测、元数据错误检测、任意问题检测三项任务上 F1 均为 **1.000（零误报、零漏报）**；纯模型基线幻觉 DOI 检测 F1 仅 **0.621**，且产生 23 次误报。错误分析表明，纯模型只能依赖臆想的“格式规律”，既漏掉格式规范的高危幻觉、又冤枉格式非典型的真实文献。

---

## 1. 问题与动机

### 1.1 引用层面的两类问题

1. **幻觉/失效 DOI**：DOI 字符串语法合法、前缀真实（属于某注册机构），但后缀对应的文献并不存在。这类问题最难人工发现——编辑或审稿人通常不会逐条点开 DOI。
2. **题录错配**：DOI 真实存在，但正文参考文献中作者、年份、标题或期刊与其元数据不一致（引用错配、张冠李戴）。

### 1.2 为什么纯模型不可靠

- 模型参数中只包含训练语料里出现过的文献，对海量、长尾、近年的论文没有覆盖；
- 它无法区分“一个不著名但真实的 DOI”与“一个格式合法但被篡改/编造的 DOI”；
- 当被要求给出结论时，模型倾向于**依据表层格式规律猜测**，这同时造成漏报（格式规范的幻觉）与误报（格式非典型的真文献）。

**科学假设（H1）**：引用核查是一个**需要外部事实检索**的任务；一个强制联网、逐字段比对、证据留痕的 Agent，应显著优于同等模型在离线下的表现，尤其在**误报率（特异度）**上。

## 2. 方法

### 2.1 Agent 架构

核查 Agent 运行在 SciencePal 的通用沙箱 runtime（可执行命令、联网、读写文件、安装软件），系统提示词规定了确定性的核查流程：

- **阶段一 · 引用核查**
  - C1 DOI 有效性：在沙箱内 `curl https://api.crossref.org/works/{doi}`，以真实 **HTTP 200/404** 判定存在性；
  - C2 元数据逐字段严格比对：将 Crossref 返回的 **年份（issued.date-parts）、作者、标题、期刊、卷/期/页码**与待审条目逐字段比对，任一不一致即 `metadata_match=false` 并给出 `confirm`，**禁止仅因 HTTP 200 就放行**；
  - C3 论断-证据一致性：正文论断是否与所引文献主题相符；
- **阶段二 · 方法学/统计审查**（M1 研究设计、M2 样本量与功效、M3 统计表述、M4 数据-结论复算、M5 选择性报告）；
- **输出**：人类可读中文报告 + 末尾固定 schema 的 JSON（`references[].{item_id,doi_status,metadata_match,verdict,evidence_url,issue}`），便于自动评分与系统集成。

关键工程约束：**禁止凭记忆给结论**；每条引用必须有可点击的证据 URL 与 HTTP 状态；无法确证时标 `suspect` 并提示人工复核。

### 2.2 纯模型离线基线（对照）

为公平对照，基线使用**同一平台、同一默认模型**，但移除其获取外部事实的能力：

- 通过 `PUT /agents/{id}` 设置 `agentpress_tools={"execute_command":{"enabled":false},"web_search":{"enabled":false}}`；
- 发起任务时传 `web_search_on=false`；
- 系统提示词明确“纯文本环境、无任何工具、必须完整输出 JSON”。

> 实践中发现，仅在提示词里写“禁止联网”并不可靠，只关闭 `web_search` 也挡不住沙箱内的 `curl`；因此在 API 层关闭 `execute_command`，并用运行时事件审计作为最终保证（见 3.3）。

## 3. 评测设计

### 3.1 金标准基准的自动构造（可复现）

`scripts/build_benchmark.py` 调用 Crossref REST API 自动构造三类条目（每种子 12 条，比例约 6 valid / 3 not_found / 3 mismatch）：

- **valid（真实）**：从 2015–2025 年的普通期刊论文池抽取（过滤会议摘要、增刊、作者缺失），保留真实题录；
- **not_found（虚构 DOI）**：取一篇真实论文的真实前缀与格式，**仅篡改后缀数字**（如 `10.1016/j.diabres.2022.109552` → 同格式的 `...99999`），并在构造时**实时请求 Crossref 确认 404**。刻意使用过去年份，避免模型靠“未来年份”推理侥幸答对；
- **mismatch（题录错配）**：真实 DOI 配错误题录，年份 / 作者标题 / 期刊三类均衡；标题篡改采用“替换核心实词为领域外词（Quantum/Blockchain 等）”，避免被误当作良性截断。

### 3.2 开发集 / 测试集隔离

- 种子 42、201 仅作为**开发集**用于迭代提示词（例如据此补强了 C2 逐字段比对规则）；
- 最终指标在**未参与任何调参**的种子 7 / 123 / 2024 / 2025（共 **48 条**）上报告，防止在测试集上过拟合。

### 3.3 离线有效性审计（对照成立的关键）

仅“关闭工具”还不够，还需要证明基线在运行时确实没有拿到外部数据。本工作对每个 run 的 SSE 原始事件流（`output/runs/{run_id}.jsonl`）重放并审计（脚本 `scripts/audit_runs.py`）：

- 若 `execute_command` 的实际返回中出现 `HTTP 200/404` 或学术 API 元数据，判为“实际联网”；
- 若工具返回 `runtime=blocked / reason_code=tool_unavailable / permission`（含平台内置 `verify-bib` 技能因缺少 `execute_command` 被阻止），判为“尝试被拒、未获数据”。

审计结论（8 个测试 run 全部符合预期）：

| 方法 | 期望 | 实际获得外部数据 | 工具调用 |
|---|---|---|---|
| 核查 Agent ×4 | 联网 | 是（全部） | 22 / 2 / 22 / 3 |
| 离线基线 ×4 | 离线 | **否（全部）** | 3（其中 2 次被拒）/ 0 / 0 / 0 |

### 3.4 指标

对三项任务分别计算精确率（P）、召回率（R）、F1、特异度（Specificity，真实条目被正确放行的比例）与准确率（Accuracy）。

## 4. 结果

### 4.1 总体指标（n = 48）

| 任务 | 方法 | P | R | F1 | Specificity | TP | FP | FN | TN |
|---|---|---|---|---|---|---|---|---|---|
| 幻觉 DOI 检测 | 离线基线 | 0.529 | 0.750 | **0.621** | 0.778 | 9 | 8 | 3 | 28 |
| 幻觉 DOI 检测 | 核查 Agent | **1.000** | **1.000** | **1.000** | **1.000** | 12 | **0** | **0** | 36 |
| 元数据错误检测 | 离线基线 | 0.778 | 0.875 | **0.824** | 0.750 | 21 | 6 | 3 | 18 |
| 元数据错误检测 | 核查 Agent | **1.000** | **1.000** | **1.000** | **1.000** | 24 | **0** | **0** | 24 |
| 任意问题检测 | 离线基线 | 0.719 | 0.958 | **0.821** | 0.625 | 23 | 9 | 1 | 15 |
| 任意问题检测 | 核查 Agent | **1.000** | **1.000** | **1.000** | **1.000** | 24 | **0** | **0** | 24 |

核查 Agent 三项任务全部 **F1 = 1.000，零误报、零漏报**；基线整体召回不低（任意问题 R=0.958），但代价是大量误报，且在最关键的幻觉 DOI 任务上 F1 仅 0.621、特异度仅 0.778。

### 4.2 错误模式分析（为什么基线“看起来会查”其实不可靠）

**基线的 3 个漏报（幻觉 DOI 被放行）**：

- `10.1109/access.2019.2991190`、`10.55248/gengpi.6.0625.16682`、`10.21275/sr231015260210`
- 这些恰好是**前缀真实、格式最规范、最具迷惑性**的 DOI——而这正是真实攻击/幻觉中最危险的一类，纯模型无法辨识。

**基线的 8 个误报（真实 DOI 被冤枉）**：

- 对 Bentham 系列 `10.2174/15734056mte2nnjcoy` 等，判其“后缀含字母、不合规”；
- 对 IJSR 系列 `10.21275/ms2312181849`、`10.21275/sr231015173828` 等，判其“不符合该刊 ART 前缀格式”。
- 这些**臆想的“格式规则”本身是错的**（这些期刊确有字母后缀 / ms、sr 编号），导致真实文献被否决。

这一“高召回 + 高误报”的组合在审稿场景中不可用：错误否决真实引用会冤枉作者、制造大量返工；而核查 Agent 以真实 HTTP 状态与元数据为准，杜绝了这类系统性偏差。

### 4.3 假设检验

H1 得到支持：联网核查 Agent 相对同模型离线基线，在幻觉 DOI 检测上 F1 从 0.621 提升至 1.000，特异度从 0.778 提升至 1.000；且差异主要来源于**误报的消除**（FP 8 → 0），符合“该任务本质需要外部事实检索”的判断。

## 4.4 Layer-2 定性案例：撤稿识别与方法学复算

Layer-1 量化了题录层能力；Layer-2 进一步用两个端到端案例展示“出版状态”与“方法学/统计”层（详见 `results/layer2/LAYER2_CASES.md`）。

**案例 A（真实）· 撤稿识别**：输入一篇被当作正常引用、题录完整的文献——Obokata 等 *STAP 细胞* 论文（`10.1038/nature12968`）。Agent 联网请求 Crossref 后发现其标题为 **“RETRACTED ARTICLE: …”**，并定位到官方撤稿通知 `10.1038/nature13533`，判 `retracted=true`；同批正常对照（LeCun, *Deep learning*）正确放行。撤稿在题录层完全合法，只有核查当前出版状态才能发现。

**案例 B（可复算的合成测试稿件）· 方法学审查**：为避免对真实作者的无据指控，使用明确标注为虚构的教学稿件并预埋方法学问题。Agent 在隔离沙箱中安装并运行 scipy **实际复算**：

- 作者报告“高剂量 vs 安慰剂 p=0.03、低剂量 vs 安慰剂 p=0.04”，复算为 **p=0.206 / 0.138（t=1.327 / 1.573），均不显著**；单因素 ANOVA p=0.284；Bonferroni 校正后 0.09/0.12；
- 事后功效仅 0.235，达到 80% 功效需每组约 37 例（报告 n=8）；
- 据此完整定位预埋的 7 项问题：p 值与数据矛盾（high）、以两两 t 检验替代 ANOVA 且未校正（high）、样本量不足（high）、非随机未设盲（medium）、选择性报告（high）、因果过度外推（high）、统计表述不规范（medium）。

复算的关键数值（p≈0.206）与预埋金标准一致，说明 Agent 能以可复算的定量证据推翻作者的统计结论，而不是停留在主观印象。至此，核查覆盖题录、出版状态、研究设计与统计三个层面。

## 6. 局限与未来工作

1. **Layer-1 聚焦题录层，Layer-2 为小样本定性**：撤稿与方法学能力已通过案例 A/B 验证端到端可行性，但尚未形成大规模量化基准（Layer-2 撤稿目前依赖 Crossref 标题撤稿标记与 `update-to` 关系，覆盖度受出版商回传质量影响）；
2. **数据源单一**：目前以 Crossref 为主，计划接入 PubMed、Semantic Scholar、OpenAlex 与中文文献库做多源交叉验证；
3. **边界日期**：在线优先 / 正式见刊的多个日期字段存在歧义，报告以证据原文呈现、交人工终判；
4. **定位为辅助工具**：系统对不确定项输出 `suspect` 而非武断结论，最终判定保留人工复核。

---

## 7. 数据与伦理

评测数据全部来自公开 Crossref 元数据，金标准 DOI 状态在构造时实时核验；仅使用题录，不涉及付费全文或个人信息。工具旨在帮助作者自检与编辑审稿，提升学术诚信，不替代同行评议。
